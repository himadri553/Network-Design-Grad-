Code edits to change sender/receiver logic
sender.py
Replace/augment the implicit 5-second recv timeout with an explicit countdown-timer mechanism that matches the RDT 3.0 FSM (Wait for ACK 0/1 states, start_timer/timeout/stop_timer).
Remove the retries < 5 cap in run_tx_sc1 — true RDT 3.0 retransmits indefinitely until a valid ACK arrives; a hard cap will cause premature failures at high loss/error rates (50–95%) needed for the plots.
Add run_tx_sc4 (Option 4 — ACK loss): after receiving an ACK, run it through a new helper.inject_loss(ack_packet, loss_rate) that returns None with probability loss_rate, then let the existing timeout/retransmit path recover — mirrors how run_tx_sc2 already calls inject_error.
Add run_tx_sc5 (Option 5 — data loss): sender side is unaffected (loss happens at the receiver), so it can just delegate to run_tx_sc1, same as run_tx_sc3 does today.
receiver.py
Add run_rx_sc4 — delegates to run_rx_sc1 (loss happens at the sender for Option 4), mirroring run_rx_sc2.
Add run_rx_sc5 (Option 5 — data loss): after rx_receive, pass the packet through helper.inject_loss; if it's dropped, do not send any ACK and keep listening (this is the key behavioral difference from run_rx_sc3's bit-error injection, which still ACKs).
helper.py
Add inject_loss(packet, loss_rate) — returns None with given probability (parallel to the existing inject_error).
Add plot_path_sc4 / plot_path_sc5 constants and create those directories alongside the existing plot_path_sc1..3.
